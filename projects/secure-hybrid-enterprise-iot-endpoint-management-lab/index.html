    Secure Hybrid Enterprise, IoT & Endpoint Management Lab

    Hands-on modernization of a mixed small-business environment using enterprise firewalling, security-zone segmentation, management-plane hardening, least-privilege service policy, protected storage/printing, and validated IoT/LoRaWAN service continuity.

    Active Hands-On PortfolioSolution Architecture / IT OperationsPublic case study

    Executive Overview

    This case study documents the staged modernization of a real mixed small-business technology environment using enterprise-style architecture, change control, rollback planning, and validation. The starting environment combined users, infrastructure, storage, printing, wireless access, and IoT systems on broadly shared network paths. The target is a controlled enterprise foundation in which management, users, storage, printers, servers, lab systems, guests, and IoT/OT workloads are separated by security zone and connected only through explicit policy.

    The work is intentionally sequenced rather than performed as a single redesign. Each change captures current state, prepares the target service path, validates business functionality, and preserves a rollback option before the next dependency is moved.

    Business & Architecture Problem

    The original environment functioned, but several unrelated device classes shared the same user network. That design increased east-west trust, mixed administrative and business traffic, and made it difficult to apply least-privilege policy. The modernization program therefore focuses on service continuity while reducing implicit trust and improving operational control.

    Target Architecture

    The target architecture separates management, servers, protected storage, users, IoT/OT, printers, guests, and lab/testing systems. Inter-zone access is explicitly governed by business need instead of broad network adjacency.

    Network Segmentation Foundation — Current Progress

    The current implementation has moved from management hardening into workload isolation. Dedicated IoT, printer, and storage zones are now operational, with the dedicated management plane next.

    Security & Operations Remediation

    CHG-001 — DHCP Gateway Remediation PASS

    Corrected a stale DHCP gateway configuration and established deterministic routing on the management workstation while preserving Internet access and administrative reachability.

    CHG-002 — WAN Administrative Access Hardening PASS

    Removed unnecessary web-management and auxiliary administrative services from the WAN-facing interface while retaining limited troubleshooting capability.

    CHG-003 to CHG-005 — Privileged Access Governance PASS

    Introduced a named MFA-protected administrator restricted to the management network, converted the built-in administrator into an emergency break-glass account, and removed an unused privileged account.

    CHG-006 — Logging Baseline PASS

    Improved denied-traffic visibility while deliberately avoiding excessive high-volume session logging until persistent external logging is implemented.

    CHG-007 — DNS Path Correction PASS

    Removed an unintended ISP-provided DNS override, renewed the client lease, and validated successful name resolution against the intentionally configured system resolvers.

    CHG-008 — Management-Plane Separation PASS

    Removed web administration from the ordinary user network while preserving management access through the existing administrative path. Validation confirmed that the user network could no longer reach the firewall management interface over HTTPS.

    CHG-009 — IoT Segmentation & End-to-End Service Validation PASS

    A wired LoRaWAN/IoT gateway was migrated out of the shared user network and into a dedicated IoT security zone. The migration preserved outbound connectivity while restricting access to required management and application services only.

    Validated end to end: VLAN and DHCP migration, outbound connectivity, restricted management access, local network-server administration, real endpoint join and application uplinks, explicit MQTT policy, raw broker publish/subscribe, and application-level ingestion/decoding of live telemetry.

    CHG-010 — Infrastructure Address Stabilization PASS

    Critical service dependencies were stabilized with centrally managed DHCP reservations. This removed avoidable address drift from firewall objects and service integrations while retaining central network control rather than relying on manually configured endpoint addresses.

    CHG-011 — Printer Security-Zone Segmentation PASS

    A shared multifunction printer was migrated from the user network into a dedicated printer zone. Access from the user network is limited to required printing and status services instead of general connectivity.

    • Dedicated printer VLAN and DHCP scope created before migration.
    • Stable printer reservation established.
    • RAW printing, IPP, and LPR connectivity validated after migration.
    • Business printing functionality preserved.
    • Web administration from the user network remains blocked by design.

    CHG-012 — Protected Storage Segmentation PASS

    Network-attached storage was migrated from the shared user segment into a dedicated storage zone. Rather than allowing the full user network to reach protected storage, SMB access is scoped to explicitly authorized endpoints.

    • Dedicated storage VLAN and DHCP scope created before migration.
    • Stable storage reservation established.
    • Host-scoped SMB policy limits access to approved endpoints.
    • Windows and macOS access validated after migration.
    • Authentication and share enumeration validated.
    • Real create/read/delete operations completed using non-production test data.
    • Storage web administration remains withheld from the ordinary user network pending management-VLAN implementation.

    Troubleshooting & Fault Isolation

    The work deliberately separates network, transport, service, and application evidence. Firewall counters are not treated as proof of application success. For IoT, the path was validated independently through network-server events, packet capture, MQTT publish/subscribe, and application ingestion. For storage, connectivity was separated from authentication and permissions before the NAS was moved. This prevented an SMB credential issue from being misdiagnosed as a network fault.

    Change-Control Method

    • Capture current state before every meaningful change.
    • Create or preserve a rollback path before moving a dependency.
    • Build the destination network and firewall policy before migrating the device.
    • Make one controlled infrastructure change at a time.
    • Validate both security behavior and business functionality after migration.
    • Record failed assumptions and corrections instead of hiding them.
    • Separate implemented controls from future-state recommendations.

    Architecture Decisions & Trade-offs

    • Incremental segmentation: preserves availability while security zones are introduced one workload at a time.
    • Central DHCP reservations: provides stable infrastructure dependencies without spreading manual static-address configuration across devices.
    • Service-specific printer access: preserves printing while withholding administrative interfaces from ordinary users.
    • Host-scoped storage access: protects sensitive storage more aggressively than a broad user-subnet allow rule.
    • Management access deferred to the management plane: storage and printer administration will move to the dedicated management VLAN rather than being opened temporarily from the user network.
    • Validate at multiple layers: routing, transport, authentication, service behavior, and application outcomes are tested independently.
    • Document licensing reality: expired subscription-backed security services are not represented as active protection.

    Enterprise Infrastructure Roadmap

    The current work represents the Network Segmentation Foundation, not the completed enterprise environment. The broader Enterprise Infrastructure Baseline v1.0 will continue through:

    • Dedicated management VLAN and privileged infrastructure-management path.
    • Server and virtualization architecture.
    • Identity and access architecture.
    • Endpoint management using MDM and MAM.
    • Endpoint security, compliance, encryption, and patching.
    • Guest/wireless segmentation and access design.
    • Centralized logging, monitoring, alerting, and configuration backup.
    • Storage protection, backup, and restore testing.
    • Firewall-policy optimization and final operational validation.

    Leadership Perspective

    The objective is not simply to configure individual devices. The work demonstrates architecture sequencing, risk reduction, service continuity, change governance, fault isolation, documentation, and the ability to move between business requirements and hands-on implementation. The IoT/OT layer will be expanded only after the enterprise foundation is mature, allowing operational technology to be integrated into an intentionally governed environment rather than an unfinished network.

    Public Disclosure

    This case study intentionally sanitizes infrastructure evidence. Exact addressing, hostnames, MAC addresses, serial numbers, account names, credentials, SSIDs, security tokens, NAS share names, radio identifiers, tenant/application IDs, and screenshots containing sensitive administrative data are withheld or redacted.
